06 / Concurrencia Crítica

El Gran As Bajo la Manga: Bloqueo Pesimista

SELECT ... FOR UPDATE
El Peligro: Race Conditions

Durante una campaña viral (ej: recaudación para el tomógrafo), dos donantes simultáneos o la concurrencia entre un Webhook de Mercado Pago y la aprobación administrativa podían leer el mismo saldo y sobre-recaudar o desincronizar la base.

La Solución Implementada

Se configuró una transacción atómica aislada en Sequelize con bloqueo pesimista exclusivo de fila (lock: transaction.LOCK.UPDATE).

  • 1. La Transacción A bloquea la fila en Postgres.
  • 2. La Transacción B se coloca en cola ordenada esperando liberación.
  • 3. Se verifica que el aporte no sobrepase la meta remanente.
  • 4. Commit atómico del saldo acumulado.

07 / Seguridad Robusta

Blindaje de Grado Médico: OWASP & Criptografía

Arquitectura de Confianza Cero

HMAC-SHA256 en Webhooks

Cada notificación de pago entrante de Mercado Pago se valida criptográficamente contra el Secret Token. Imposible inyectar pagos falsos.

DOMPurify & Anti-ReDoS

Sanitización completa del contenido HTML de noticias para neutralizar Cross-Site Scripting (XSS), junto a defensas contra expresiones regulares catastróficas.

Rate Limiters por IP

100 peticiones globales / 15 min, 10 logins / 15 min y tope de 5 donaciones / hora para frenar ataques de fuerza bruta y raspado de datos.

Resend API sobre HTTPS

Reemplazo del SMTP tradicional por la API REST de Resend en el puerto seguro 443. Cero bloqueos de firewalls hospitalarios y entregabilidad del 99.8%.
